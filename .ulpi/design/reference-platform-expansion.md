# 文档参考界面与功能补全规范

> 绑定 `.ulpi/design/DESIGN.md`。Every screen must read as the same product if placed side by side.

## Design Read

把文档中的蓝色大屏升级为可连续值守的工业控制台：地图和工艺脉络是主角，数据围绕任务组织，告警与控制始终可追溯。

## 参考图设计 DNA

- 取用：深海军蓝工作面、青色管网拓扑、顶部任务导航、地图与指标联动、表格优先的高密度数据表达。
- 拒绝：多重外发光、无意义科技边框、所有模块都做成独立卡片、为装饰而存在的扫描线和动态粒子。
- 综合：以 `.ulpi/design/DESIGN.md` 的青蓝“工艺脉络线”为唯一视觉签名，地图、趋势、DMA 和调度流程共用同一套状态语义。

## 信息架构

| 顶部任务 | 页内视图 | 主要输出 |
|---|---|---|
| 监控总览 | 全厂态势、指标、告警摘要、三水池摘要 | 现在是否安全 |
| 水网监控 | 概化图、GIS、三维、设备清单 | 异常在哪里 |
| 运行分析 | 用水、压力、漏损、DMA | 为什么异常、影响多大 |
| 智能调度 | 方案中心、任务编排、执行监控 | 应采取什么动作、是否执行成功 |
| 告警事件 | 告警、事件、工单、报表 | 谁负责、何时闭环、如何复盘 |

报表不是第六个主菜单。它位于“告警事件”的页内视图，避免首层入口继续膨胀。

## 核心流程

### Flow: 从异常发现到闭环

**目标：** 值班员从总览发现异常，定位到分析结论，形成事件或调度动作并完成复盘。

1. 总览显示告警和风险指标，用户进入水网监控定位设备或 DMA。
2. 用户进入运行分析，在用水、压力、漏损或 DMA 视图确认趋势和影响范围。
3. 需要运行调整时进入智能调度，比较方案、校核风险并下发；需要现场处理时创建事件和工单。
4. 执行监控展示进度、剩余时间、双泵状态和水位偏差。
5. 告警恢复后仍保留事件，完成效果验证后关闭并进入报表复盘。

**异常处理：** 离线时保留最后数据并禁止下发；部分测点离线时标记数据完整率；权限不足时保留查看能力并隐藏控制动作；刷新后保持当前顶部任务和页内视图。

## 页面与组件

### TaskNavigation

- 五个顶部任务使用按钮式语义导航，当前项设置 `aria-current="page"`。
- 点击只切换工作区，不依赖锚点滚动；桌面端固定，窄屏横向滚动。
- 默认、悬停、焦点、选中和禁用状态全部使用锁定令牌。

### AnalysisCenter

- 页内标签：用水分析、压力分析、漏损分析、DMA 分区。
- 用水视图输出总量、计划偏差、回用率、单位产品耗水以及 24 小时趋势。
- 压力视图输出合格率、高低压点、阈值来源和多测点趋势。
- 漏损视图输出漏损率、最小夜间流量、疑似漏点和诊断建议。
- DMA 视图输出分区边界、进出表计、责任人、产销差和事件入口。
- 图表必须同时有数字、单位、图例和文字结论，不只依赖颜色。

### DispatchCenter

- 页内标签：方案中心、任务编排、执行监控。
- 三个可比较方案分别体现节能、稳妥和防洪目标；同一时刻只允许一个主动作“应用方案”。
- 执行视图显示水位目标、双向泵方向/频率/功率、进度、风险裕度和控制反馈。
- 下发继续复用现有二次确认、权限校验、互斥与离线阻断。

### EventCenter

- 页内标签：告警、事件、工单、报表。
- 告警状态链：发生、确认、分派、处置、恢复、验证、关闭。
- 工单显示负责人、期限、来源事件和处理状态；报表显示模板、周期、状态、生成时间和导出动作。
- 列表支持空、加载、错误、部分成功和权限不足状态。

## 响应式与可访问性

- 1920×1080 为目标视口；1280px 以下缩减辅助摘要；768px 以下主菜单与页内标签横向滚动。
- 所有点击目标至少 44px；键盘可完成主菜单、页内标签、方案选择和确认。
- 当前任务使用 `aria-current`，页内标签使用 `role="tablist"` / `role="tab"` / `aria-selected`。
- 状态变化通过 `role="status"` 宣告；错误信息提供明确恢复动作。
- 动效只用于视图切换和管线状态变化，使用锁定时长并遵守 `prefers-reduced-motion`。

## Design Pre-Flight

- Identity lock：全部颜色、字体、间距、圆角和动效来自 `DESIGN.md`，新增系统外令牌 0。
- Anti-slop：无紫色渐变、无玻璃卡片、无嵌套卡片、无三等分营销卡片、无装饰性编号。
- State coverage：加载、空、错误、离线、部分离线、权限不足和执行中均有承载位置。
- Accessibility：可见焦点、键盘路径、ARIA 标签、非颜色状态文本和 reduced-motion 均已规定。
- Layout craft：状态条、地图/拓扑、表格、趋势图、流程轨道五类布局按任务组合。
- Cognitive load：顶部严格 5 项；每个页面一个主动作；页内标签渐进披露。
- 自评：distinctiveness 4，hierarchy 4，consistency 4，accessibility 4，state coverage 4，copy 4，restraint 4，motion 3，总分 31/32。
- 修订说明：报表移入事件中心，避免新增第六个顶部入口；科技感集中在工艺脉络和数据状态，不增加装饰特效。

## Build Handoff

目标为当前 Vue 3 SPA。继续使用 Element Plus 与既有组件，不迁移框架，不重新实现组件库。实现必须严格遵循本规范和 `.ulpi/design/DESIGN.md`，不得重新设计。

验收标准：

- 五个顶部任务可真实切换工作区，并保留 `aria-current`。
- 运行分析覆盖用水、压力、漏损和 DMA 四个视图。
- 智能调度覆盖方案、任务和执行三个视图，并保留二次确认与离线阻断。
- 告警事件覆盖告警、事件、工单和报表四个视图。
- 现有总览、节点选择、告警确认、刷新和调度下发行为不回退。
- 1280px 与 768px 断点无菜单折行、遮挡或横向页面溢出。
