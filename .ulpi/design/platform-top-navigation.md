# 平台顶部主导航界面规范

> 绑定 `.ulpi/design/DESIGN.md`。Every screen must read as the same product if placed side by side.

## Design Read

把原本分散在左侧的入口改造成值班台顶部的“任务跑道”：当前任务始终可见，运行上下文靠右固定，工作区获得完整横向空间。

## 信息架构

| 顶部入口 | 当前原型锚点 | 完整产品下属能力 |
|---|---|---|
| 监控总览 | `#overview` | 全厂态势、关键指标、三维/GIS/概化视图切换、设备总览 |
| 水网监控 | `#network` | 管网、泵站、阀门、水池、仪表、图层与设备定位 |
| 运行分析 | `#analysis` | 用水、压力、漏损、DMA、趋势与对比 |
| 智能调度 | `#pools` | 三水池调度、方案比选、任务编排、执行监控、历史调度 |
| 告警事件 | `#alarms` | 报警、事件、工单、升级、复盘 |

报表管理和系统管理不与高频值班任务竞争首层空间。完整产品中，报表管理进入用户/应用菜单；系统管理只对管理员显示。若后续数据证明报表为每日高频入口，可替换“水网监控”为“业务中心”下拉组，但首层仍保持不超过 5 项。

## 主流程与状态

1. 用户进入平台，默认选中“监控总览”，焦点和 `aria-current` 与当前入口一致。
2. 选择顶部入口后滚动或路由到对应工作区，顶部导航保持固定。
3. 运行上下文显示当前班次；厂区、数据时间、通信状态和值班员继续由二级页头承载。
4. 离线时顶部结构不变化，页面级离线横幅继续阻止控制下发。
5. 视口小于 1280px 时隐藏品牌全称与班次摘要；小于 768px 时菜单横向滚动，入口不折行、不缩写。

## 组件：TopNavigation

- 文件：`frontend/src/components/TopNavigation.vue`
- 数据：`{ label: string; href: string }[]`
- 默认状态：`#overview` 选中。
- 选中状态：使用 `elevated` 背景、`text` 文本和 2px `accent` 下划线。
- 键盘：按文档顺序 Tab；Enter 激活锚点；焦点使用全局 2px `accent` 轮廓。
- 读屏：`nav[aria-label="平台主导航"]`；当前入口使用 `aria-current="page"`。
- 动效：只使用浏览器平滑滚动；`prefers-reduced-motion` 时由全局规则缩短。
- 空/错/加载：导航是静态壳层，不依赖接口；业务内容的状态由各页面承载。

## Design Pre-Flight

- Identity lock：0 个系统外颜色、字体、圆角或图标；继续使用 Element Plus 体系。
- Anti-slop：无渐变、无玻璃态、无装饰图标、无嵌套卡片；“任务跑道”是本平台的工业标牌签名延伸。
- 状态：默认、hover、focus、active、窄屏横向滚动、离线上下文均有处理。
- 可访问性：语义导航、当前页声明、可见焦点、文本对比沿用已记录 AA 令牌。
- 认知负荷：首层 5 项，每项按用户任务而非技术对象命名。
- 自评（满分 32）：distinctiveness 4，hierarchy 4，consistency 4，accessibility 4，state coverage 3，copy 4，restraint 4，motion 4；总分 31。
- 修订说明：把“集水池”改为“智能调度”，因为入口应表达任务目标；把报表和系统管理移出高频首层，降低值班场景扫描负担。

## Build Handoff

目标：Vue 3 SPA 工程实现。设计系统：Element Plus，使用仓库现有依赖并以 `.ulpi/design/DESIGN.md` 主题令牌覆盖；不要重设计或手工复刻组件库组件。

验收标准：

- 桌面与移动端都只出现顶部主导航，不再出现左侧或底部主菜单。
- 顶部入口严格为 5 个，顺序和锚点与本规范一致。
- 默认入口具有 `aria-current="page"`，点击后选中态跟随。
- 1280px 和 768px 两个断点无菜单折行或内容遮挡。
- 原有实时监控、节点选择、告警确认和调度下发行为不退化。
