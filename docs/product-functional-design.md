# 氧化铝厂用水管网智能管理平台功能设计

## 1. 产品边界与用户任务

平台服务领导、调度员、运行值班员、设备管理员、节水/能源管理员和系统管理员，覆盖“监测、展示、分析、决策、控制、复盘”。首期必须让值班员快速回答四个问题：系统是否安全、异常在哪里、应该采取什么动作、动作是否执行成功。

## 2. 总体信息架构

| 任务域 | 页面/二级模块 | 核心输出 |
|---|---|---|
| 监控中心 | 监控总览、三维图、GIS 图、概化图 | 全厂态势、空间定位、工艺关系 |
| 设备与水网 | 泵站、阀门、水池、流量计、压力计、水质仪表 | 实时状态、趋势、授权控制 |
| 分析中心 | 用水、压力、漏损、DMA | 指标口径、异常诊断、节水建议 |
| 调度中心 | 三水池、方案、任务、指令、执行、历史 | 可校核方案、控制指令、执行反馈 |
| 事件中心 | 报警、事件、工单 | 确认、分派、处置、验证、关闭 |
| 报表中心 | 查询、模板、任务、审批、导出、归档 | 可追溯管理报告 |
| 系统管理 | 组织、用户、角色、参数、字典、接口、日志 | 权限、口径和审计配置 |

界面首层不照搬全部业务模块，而是按高频任务收敛为 5 个顶部入口；低频报表和管理员能力采用应用菜单/用户菜单渐进披露。

## 3. 详细功能设计

### 3.1 监控总览

- 指标：总供水、总用水、新水、回水、循环水、回用率、平均压力、瞬时流量、在线设备、异常点、节水量、能耗、计划和调度达成率。
- 空间态势：三维、GIS、概化图共享时间、区域、设备类型和选中对象。
- 交互：指标进入专题页；设备打开实时卡片；报警支持级别/区域/类型筛选与一键定位。
- 状态：实时、数据延迟、部分点位离线、全局离线、无数据、权限不足。

### 3.2 空间与实时监控

- GIS：天地图影像、抱流水定位、管线/水池/泵站图层、状态着色、聚合、闪烁、回放、量测。
- 三维：旋转、漫游、测距、设备标注和水流动画。
- 概化：供回水拓扑、上下游、联动关系与关键参数。
- 对象控制：泵启停/频率/模式，阀门开关/开度，水池目标水位。所有控制经过权限、互斥校验、二次确认和审计。

### 3.3 用水分析

- 指标总览、小时/日/周/月趋势、同比环比、分区构成、水源结构、峰谷、单耗、排名和建议。
- 每个指标展示单位、计算口径、时间范围、数据完整率和最后更新时间。
- 支持车间、工序、区域和水源联动筛选及 CSV/Excel 导出。

### 3.4 压力分析

- 总览、空间分布、多测点趋势、区域/同期对比、高低压排名、预警和报表。
- 阈值线必须标注配置来源；突变、持续低压和离线分别处理，不能共用一个“异常”状态。

### 3.5 漏损与 DMA

- 总供水、有效用水、漏损量/率、最小夜间流量、产销差、压力关联和模型诊断。
- DMA 配置边界、进出表计、阀门和责任人；异常转事件后进入定位、派单、维修、复核、销项闭环。

### 3.6 三水池智能调度

- 输入：降雨过程、产流预测、三池水位/库容/上下限、双向泵曲线、生产需求、管线能力、电价和时间步长。
- 目标：水位安全优先，其次供水连续，再权衡腾库速度、启停次数和能耗。
- 方案：节能优先、稳妥平衡、防洪优先；展示目标水位、预泄量、泵时长、频率序列、能耗、风险和评分。
- 应用前：校核水位、频率、管线和供水安全；展示校核依据与阻断原因。
- 执行中：状态、进度、剩余时间、腾库完成度、风险裕度、能耗、水位偏差、双泵方向/频率/流量/压力/功率和指令反馈。
- 异常：自动降级、重算或人工接管；暂停、恢复和终止均需记录原因与操作者。

### 3.7 报警、事件与工单

- 报警分级：提示、低、中、高、紧急；支持声音和升级规则配置。
- 流程：发生 → 确认 → 分派 → 处置 → 恢复 → 效果验证 → 关闭。
- “恢复”只代表实时值正常，不能自动关闭事件；超时自动升级并通知责任人。

### 3.8 报表管理

- 查询、在线预览、系统/自定义/共享模板、章节编排、定时生成、审批、PDF/Excel/CSV 导出和归档。
- 每份报表记录数据范围、生成时间、数据源、模板版本、状态、审批和导出记录。

### 3.9 系统、权限与审计

- RBAC 叠加区域/对象数据权限；控制权限与查看权限分离。
- 阈值、指标口径、字典、接口和算法模型版本均可配置并留痕。
- 接口支持断线重连、补传、控制超时、幂等重试和主备切换。

## 4. 页面通用规则

- 顶部第一层只承载跨任务导航；页头承载厂区、数据时间、通信和值班员；页内标签承载同一任务的视图切换。
- 时间、区域、设备和对象筛选跨三种空间视图保持；返回专题页时恢复筛选。
- 一个视图只有一个主动作；控制动作与查询动作在颜色和位置上分级。
- 所有列表具备加载、空、部分成功、失败、重试和权限不足状态。
- 目标分辨率为 1920×1080；1280px 以下收敛上下文，768px 以下菜单横向滚动。

## 5. 分期与验收

1. 一期：总览、三视图、实时监控、报警、基础报表。
2. 二期：用水、压力、漏损、DMA 和统计报表。
3. 三期：方案、任务、泵阀联动和三水池闭环调度。
4. 四期：预测、AI 诊断、自动重算和策略优化。

验收重点：跨视图对象一致；实时值和刷新/补传有效；指标口径可追溯；调度满足上下限并正确控制双泵；执行可暂停、恢复、接管；报警—事件—工单闭环；报表可生成、预览、审批、导出和归档。

## 6. 合理性评审

- 合理：按任务而非设备对象组织首层，适合多角色共用；高风险控制仍留在业务页面，不放进全局导航。
- 合理：顶部导航释放横向工作区，对 GIS、三维和趋势图更有利，也符合用户明确要求。
- 需要控制：顶部不宜继续加入口；新增功能必须归入现有任务域或使用渐进披露。
- 需要补齐：当前代码仍是一期原型，分析、报表、权限和完整事件闭环在文档中已设计但尚未实现。
- 技术决策：继续使用仓库锁定的 Element Plus，不采用原产品文档中的 Ant Design Vue，避免双组件体系造成视觉和维护分裂。
